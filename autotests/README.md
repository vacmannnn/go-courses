# go-course-tests

Общие преподавательские автотесты для [go-courses](https://github.com/vacmannnn/go-courses).
Решения студентов остаются в их репозиториях. Этот проект собирает решение во временной
копии, запускает нужный набор тестов и возвращает exit code `0` (прошли) или `1` (не прошли).

## Что уже работает

| ДЗ | Проверки |
| --- | --- |
| 1 | `twoSum`: отрицательные числа, нули, дубликаты, разные индексы, перестановки. Порядок индексов свободный. |
| 2 | Флаги, диапазон, точный формат строк, worker limit, параллельность, 404/429/500, битый JSON, обрыв соединения, таймаут, SIGINT. |
| 3 | **Пять HTTP-тестов:** диапазон фильмов, невалидные параметры, последний фильм, Swagger, ошибка внешнего стенда и сохранение работоспособности. |

ДЗ 3 пока покрыто частично: gRPC, частичные ошибки, отмена HTTP-запросов и таймауты
сервиса требуют дополнительных тестов. ДЗ 4–10 описаны в [ROADMAP.md](ROADMAP.md),
но ещё не поддерживаются командой запуска. Неизвестный номер ДЗ завершает проверку ошибкой.
Зелёный результат означает прохождение перечисленных проверок, а не полное выполнение всех критериев ДЗ.

## Быстрый старт

Нужны Go **1.26.4+**, Python **3.9+**, Git, macOS/Linux. Внешних Go/Python-библиотек нет.
`MOVIE_BASE_URL` и `HTTP_ADDR` ниже — предлагаемый договор запуска для автопроверки;
их нужно добавить в условия курса и в конфигурацию решений.

```bash
cd ~/code/go-courses/autotests

# Проверка конкретного Go-модуля студента:
./scripts/check.sh task1 ~/code/go-homework/task1
./scripts/check.sh task2 ~/code/go-homework/task2 --report reports/task2.json
./scripts/check.sh task3 ~/code/go-homework/task3 --package cmd/server --report reports/task3.json

# Проверить сам набор на эталонных и намеренно сломанных решениях:
make test
make check

# Быстрая демонстрация пяти HTTP-тестов:
./scripts/check.sh task3 ./testdata/task3-good
```

Второй аргумент — каталог с `go.mod`. Если `main` лежит в `cmd/server`, передайте
`--package cmd/server`. Можно проверять любой checkout, включая ветку открытого PR.
Исходная папка не изменяется; `.git`, симлинки и служебные каталоги не копируются.
Решения с внешними локальными `replace`/симлинками нужно предварительно сделать самодостаточными.

В ДЗ 1 преподавательский тест помещается в `package main`; студенческие `*_test.go`
временно исключаются из копии. Сигнатура: `twoSum(nums []int, target int) []int`.
Проверяются только входы с единственным решением. Случаи без решения не добавляют новых требований.
Оформление PR, вызов из `main`, доступ преподавателя и авторство остаются на ревью.

Для ДЗ 2–3 сначала собирается бинарник, затем проверяется его внешнее поведение.
Для тестов используется свой HTTP-стенд: интернет и реальный `homeworksite.site` не нужны
(скачивание зависимостей самого студенческого решения при сборке может требовать сеть).

## Контракт запуска

### ДЗ 2

- Приложение читает `MOVIE_BASE_URL`, например `http://127.0.0.1:54321`.
- В обычном запуске значение по умолчанию: `https://homeworksite.site`.
- HTTP-путь: `/{id}/info.0.json`.
- Флаги: `--from`, `--to`, `--workers` (10), `--timeout` (`5s`, Go duration).
- Успешная строка: `id — title — year — director` (длинное тире `—`, пробелы).
- Порядок строк свободный; строка каждого успешного фильма встречается один раз.
- Ошибка фильма содержит его id и объяснение. Код выхода при частичной ошибке не фиксируется.
- SIGINT обрабатывается приложением; процесс быстро заканчивает работу и прекращает очередь.

### ДЗ 3

- Приложение читает `MOVIE_BASE_URL` и `HTTP_ADDR` (`127.0.0.1:<свободный порт>`).
- Запускается без обязательных аргументов командной строки. Конфигурацию можно читать из env.
- `GET /load-movies?from=1&to=3` → `200`, JSON-массив из трёх фильмов.
- Поля фильма: `id` (число), `title` (строка), `year` (число), `director` (строка).
  Дополнительные поля разрешены, порядок фильмов свободный.
- Отсутствующий параметр, нечисловой параметр или `from > to` → `400` с непустым объяснением.
- `GET /last-movie` → `200` и JSON последнего фильма. Стенд содержит последовательные id от 1.
- `GET /swagger/index.html` → `200`, HTML со словом Swagger.
- Если весь внешний стенд отвечает `500`, `/last-movie` возвращает HTTP-ошибку
  с непустым телом, сервис остаётся доступным. Точный код преобразования пока не фиксируется.

Тест Swagger — smoke check наличия страницы, не проверка полноты OpenAPI.
Тесты не требуют конкретных пакетов, интерфейсов, роутеров и алгоритма поиска последнего id.
Формат частичных ошибок не навязывается: этот случай пока не входит в набор ДЗ 3.
Общий `.proto` нужен перед добавлением gRPC-проверок.

## Структура

```text
task1/                  шаблон тестов, внедряемый рядом с twoSum
task2/                  тесты CLI
task3/                  5 HTTP-тестов
fixtures/               детерминированные фильмы
mockserver/             стенд с ошибками, задержками и счётчиками запросов
internal/harness/       запуск и остановка процессов
scripts/check.sh        единая команда
scripts/check.py        временная сборка, запуск и JSON-отчёт
scripts/ci.py           определение ДЗ по ветке и автоматический поиск решения
tests/                  проверка самого grader на правильных/сломанных решениях
testdata/               эталонные решения только для проверки grader
../.github/workflows/   собственный CI, ручной и reusable запуск
../ci-example.yml       пример подключения в студенческом репозитории
```

## Подключение GitHub Actions

Пошаговая инструкция — в [корневом README](../README.md).
Workflow находятся в `../.github/workflows/`, пример для студентов — `../ci-example.yml`.
Студент один раз копирует пример в `.github/workflows/course.yml`: номер ДЗ берётся из ветки `taskN`,
модуль и пакет `main` находятся автоматически. На каждом ДЗ менять CI-файл не нужно.
Результат появляется в Checks студенческого PR. Для локального автоматического запуска:

```bash
python3 scripts/ci.py --repo ~/code/student-homework --branch task3
```

## Пределы проверки

- Это инструмент приёмки поведения, не автоматическое выставление всех баллов.
- Для ДЗ 8 отдельно запускайте тесты студентов и считайте их покрытие; преподавательские тесты
  не должны повышать студенческое покрытие.
- Временная копия **не является sandbox**: код запускается с правами текущего пользователя.
  Для чужих решений используйте одноразовый runner/контейнер без секретов и лишних mount.
- Студент может изменить свой workflow. Для итоговой приёмки повторяйте запуск доверенного
  набора в преподавательском окружении на конкретном SHA.
- JSON-отчёт содержит revision решения и набора, если доступен Git. Незакоммиченные изменения
  в SHA не отражаются — итоговую проверку запускайте на чистом checkout.
