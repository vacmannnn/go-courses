### PostgreSQL: хранение фильмов

Нужно добавить PostgreSQL и сделать его основным источником данных для сервиса.

При старте сервис должен синхронизировать локальную БД с внешним фильм-стендом: найти последний доступный фильм, скачать отсутствующие фильмы и сохранить их в PostgreSQL.

HTTP и gRPC методы из ДЗ 3 должны сохранить старый контракт, но теперь читать данные из БД, а не ходить во внешний стенд при каждом запросе. Ручки остаются прежними.

### Конфигурация

Сервис должен читать конфигурацию из переменных окружения:

- `MOVIE_BASE_URL` — базовый URL внешнего фильм-стенда;
- `HTTP_ADDR` — адрес HTTP-сервера;
- `DATABASE_URL` — строка подключения (DSN) к PostgreSQL.

Для `MOVIE_BASE_URL` и `HTTP_ADDR` сохраняются требования ДЗ 3, включая значения по умолчанию, приоритет окружения и запуск без обязательных CLI-аргументов.

- Нужно добавить миграции и схему для хранения фильмов, жанров и актёров. Связи фильма с жанрами и актёрами можно хранить через отдельные таблицы связей или другим обоснованным SQL-способом.
- Если фильм уже есть в БД, повторная синхронизация не должна создавать дубликаты. Внешний фильм-стенд используется только для обновления локальной БД.

### Критерии оценивания

6 баллов — PostgreSQL стал основным источником данных. Добавлены миграции и схема хранения фильмов, жанров, актёров и их связей. При старте сервис находит последний фильм на стенде и загружает отсутствующие фильмы в БД; повторная синхронизация не создаёт дубликаты. Все HTTP/gRPC методы сохранили контракт и читают данные из БД, внешний стенд используется только для синхронизации. Конфигурация читается из окружения по требованиям задания.

5 баллов — Основные требования выполнены, но есть небольшой недочёт: например, некорректно применяется одно из значений конфигурации по умолчанию. Синхронизация, хранение без дублей и чтение через оба API работают.

4 балла — Фильмы сохраняются в PostgreSQL и доступны через API, но не выполнено одно из существенных требований: нет миграций, не сохраняются жанры или актёры, либо синхронизация не запускается автоматически при старте.

3 балла — PostgreSQL подключён, но переход на БД выполнен частично: часть методов продолжает читать фильмы со стенда, синхронизация пропускает отсутствующие фильмы или повторный запуск создаёт дубликаты.

0–2 балла — Работа не сдана, код не компилируется или сервис не запускается. Либо PostgreSQL фактически не используется: фильмы не сохраняются в БД или их нельзя получить через API.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).
