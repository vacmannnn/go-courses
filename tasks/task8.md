### Тестирование и простой веб-интерфейс

Задание состоит из двух частей.

Требования ДЗ 7 к конфигурации сервисов через `MOVIE_BASE_URL`, `HTTP_ADDR`, `DATABASE_URL`, `REDIS_ADDR` и `KAFKA_BROKERS` сохраняются.

Первая часть — покрыть проект тестами. Общее покрытие кода должно быть больше 70%.

Нужно протестировать основную бизнес-логику, HTTP/gRPC handlers и работу с внешними зависимостями через моки, фейки или тестовые контейнеры. Проверка `go test ./...` должна проходить успешно.

Вторая часть — добавить простой веб-интерфейс, чтобы проект можно было показать в браузере и добавить скриншот в резюме/портфолио.

Нужно сделать две HTML-страницы через `html/template`:

- страница с поисковой формой;
- страница с результатами поиска.

Веб-интерфейс должен использовать существующую логику поиска из сервиса. Отдельную поисковую логику внутри HTML handler писать не нужно.

### Критерии оценивания

6 баллов — Общее покрытие кода тестами больше 70%, go test ./... проходит успешно. Содержательные тесты проверяют основную бизнес-логику, HTTP/gRPC handlers и взаимодействие с внешними зависимостями через моки, фейки или тестовые контейнеры. Через html/template сделаны страницы поисковой формы и результатов, используется существующая логика поиска без дублирования в HTML handler. Конфигурация сервисов сохранена, в README описаны запуск тестов и открытие веб-интерфейса.

5 баллов — Покрытие больше 70%, тесты проходят, обе HTML-страницы работают и используют существующий поиск. Есть небольшой недочёт: например, не проверен отдельный сценарий ошибки или неполно описан запуск в README.

4 балла — Тесты проходят и веб-интерфейс работает, но покрытие не превышает 70% или не протестирована одна из обязательных частей: бизнес-логика, HTTP/gRPC handlers либо взаимодействие с внешними зависимостями. Либо тестовая часть выполнена полностью, но отсутствует одна из HTML-страниц.

3 балла — Выполнена только одна из двух частей задания: есть содержательные тесты, но нет веб-интерфейса, или работает веб-интерфейс, но тестов почти нет. Либо тесты нестабильны, зависят от порядка запуска или HTML handler дублирует бизнес-логику поиска.

0–2 балла — Работа не сдана, код не компилируется или обе части задания фактически не выполнены. Либо тесты не проверяют поведение приложения, а веб-интерфейс не позволяет выполнить поиск и увидеть результаты.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).
