### Логи, метрики и Grafana

Нужно добавить observability для проекта.

Требования ДЗ 9 к конфигурации контейнеров и возможности переопределить `MOVIE_BASE_URL` для `downloader-service` сохраняются.

Логи:

- добавить структурированные логи через `slog`;
- логировать входящие HTTP/gRPC-запросы, ошибки, загрузку фильмов, работу Kafka consumer/producer;
- добавить request id / correlation id;
- писать логи в stdout;
- добавить Loki и Promtail/Alloy для сбора логов;
- настроить просмотр логов в Grafana.

Метрики:

- добавить Prometheus endpoint `/metrics`;
- собирать метрики HTTP/gRPC-запросов, ошибок, времени ответа, работы Kafka, Redis и PostgreSQL;
- добавить метрики бизнес-событий: поиск фильмов, загрузка фильмов, найденные/не найденные фильмы.

Grafana:

Нужно сделать 6 дашбордов: 3 бизнесовых и 3 технических.

Бизнесовые дашборды:

- поисковые запросы: количество запросов, популярные запросы, доля пустых результатов;
- загрузка фильмов: сколько фильмов загружено, сколько ошибок загрузки, скорость обновления каталога;
- каталог фильмов: количество фильмов в БД, распределение по годам/жанрам, последний загруженный фильм.

Технические дашборды:

- API: RPS, latency, HTTP/gRPC ошибки;
- инфраструктура: PostgreSQL, Redis, Kafka, состояние подключений и ошибки;
- сервисы: состояние `catalog-service` и `downloader-service`, рестарты, потребление CPU/памяти.

Prometheus, Grafana, Loki и Promtail/Alloy должны подниматься через Docker Compose вместе с проектом. В README нужно описать команду запуска и адреса, где смотреть метрики, логи и дашборды.

### Критерии оценивания

6 баллов — Оба сервиса пишут структурированные логи через slog в stdout с request id / correlation id; логируются HTTP/gRPC-запросы, ошибки, загрузка фильмов и работа Kafka. Логи собираются через Loki и Promtail/Alloy и доступны в Grafana. Prometheus собирает метрики через /metrics: запросы, ошибки, время ответа, работу Kafka, Redis, PostgreSQL и бизнес-события. Настроены все 6 дашбордов с данными: поиск, загрузка, каталог, API, инфраструктура и состояние сервисов. Весь observability-стек запускается через Docker Compose, возможность переопределить MOVIE_BASE_URL сохранена. В README описаны запуск и адреса метрик, логов и дашбордов.

5 баллов — Логи, метрики, все 6 дашбордов и запуск через Compose работают. Есть небольшой недочёт: например, пропущена отдельная метрика на одном из дашбордов или в README не указан один из адресов для проверки.

4 балла — Логи доступны в Grafana, Prometheus собирает метрики, но дашбордов меньше 6, отсутствует часть обязательных групп метрик или request id / correlation id. Либо весь мониторинг работает, но часть компонентов приходится запускать вручную вне Compose.

3 балла — Реализовано только одно направление: сбор логов или метрик. Либо инструменты запускаются, но дашборды пустые, существенные события не логируются или данные не позволяют оценить состояние сервисов.

0–2 балла — Работа не сдана, сервисы перестали запускаться или observability фактически отсутствует. Либо конфигурации добавлены, но логи и метрики сервисов не поступают в Loki/Prometheus и недоступны для просмотра в Grafana.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).
