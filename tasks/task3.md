### HTTP/gRPC API над фильмами

В этом ДЗ CLI-приложение из прошлой задачи больше не используется. Нужно сделать Go-сервис, который предоставляет HTTP и gRPC API и внутри ходит во внешний фильм-стенд.

HTTP API:

- `GET /load-movies?from=N&to=M` — загружает фильмы со стенда в диапазоне `[from; to]` и возвращает JSON-массив фильмов.
- `GET /last-movie` — находит последний доступный фильм на стенде и возвращает его JSON.

Для HTTP API нужно добавить Swagger/OpenAPI. Swagger должен открываться в браузере по адресу:

```
localhost:<port>/swagger/index.html
```

gRPC API:

- `LoadMovies(LoadMoviesRequest) returns (LoadMoviesResponse)` — загружает фильмы со стенда в диапазоне `[from; to]`.
- `GetLastMovie(GetLastMovieRequest) returns (Movie)` — находит последний доступный фильм на стенде.

Как искать последний фильм:

- считаем, что фильмы на стенде имеют id подряд от `1` до `last_id`; (если комикс с id=99999 не найден (404), то комиксов с большим id гарантированно не будет)

Требования к обработке ошибок:

- некорректные `from`/`to` в HTTP должны возвращать `400 Bad Request`;
- некорректные аргументы в gRPC должны возвращать код `InvalidArgument`;
- ошибки внешнего стенда должны преобразовываться в понятные HTTP/gRPC ошибки;
- частичные ошибки при загрузке диапазона должны быть явно отражены в ответе;
- все запросы к стенду должны использовать `context` и таймауты.

### Критерии оценивания


6 баллов — Реализованы все HTTP и gRPC эндпоинты (/load-movies, /last-movie, LoadMovies, GetLastMovie). Swagger доступен по /swagger/index.html. Обработка ошибок корректна: 400 для HTTP, InvalidArgument для gRPC. Контекст и таймауты используются, сериализация JSON/Protobuf правильная. Код разделён на пакеты (не всё в main).

5 баллов — Все эндпоинты работают, но есть мелкие недочёты: например, Swagger не открывается, или gRPC-метод не использует контекст, или код содержит дублирование, но функциональность полная.

4 балла — Реализованы только HTTP или только gRPC (одно из двух отсутствует). Или есть оба, но не работает валидация входных данных (например, from/to не проверяются). Или отсутствует обработка ошибок (при проблемах со стендом сервис падает).

3 балла — Эндпоинты есть, но они не ходят в стенд (возвращают заглушки), или используется неправильный HTTP-метод, или gRPC не стартует. Нет Swagger.

0–2 балла — Код не компилируется, или сервис не запускается, или эндпоинты не соответствуют заданию (например, возвращают не JSON). Структура нарушена.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).
